# PocketLand UI 리디자인 지시서

## 1. 현재 UI 문제 진단

현재 UI는 홈, 게임, 캐릭터 도감 화면 모두 모바일 게임풍 장식을 일부 갖추고 있지만, 화면별 위계와 컴포넌트 규칙이 안정적으로 정리되어 있지 않다. `global.css`에 로비, 컬렉션, 게임 HUD 스타일이 한 파일 안에 누적되어 있으며, 동일한 버튼/카드 계열이 화면마다 조금씩 다른 반경, 그림자, 배경 그라데이션을 사용한다. 이 때문에 전체가 하나의 게임 앱처럼 보이기보다 여러 시안이 합쳐진 느낌을 준다.

가장 큰 즉시 수정 대상은 한국어 UI 문자열과 이모지 표시가 깨져 보이는 점이다. `HomePage.tsx`, `CharacterSelectPage.tsx`, `CharacterCard.tsx`, `GameScreen.tsx`, `GameHud.tsx`, `GameResultModal.tsx`, `characterData.ts`, `characterPresentation.ts`의 표시 문자열이 깨져 있어 실제 사용자는 버튼 의미, HUD 항목, 캐릭터 이름을 읽을 수 없다. 리디자인 구현 시 시각 스타일보다 먼저 표시 문구를 정상 한국어로 복구해야 한다.

홈 화면은 이미 로비형 구성을 시도하고 있으나, 상단 빠른 메뉴, 하단 내비게이션, 미션/출석/보상 카드가 MVP 범위를 넘어서는 장식 정보처럼 보인다. 게임 화면은 HUD가 4열로 촘촘하게 압축되어 있고, 진행률/목표/생명/코인의 우선순위가 충분히 명확하지 않다. 캐릭터 도감은 수집 화면을 목표로 하지만 카드 안 정보가 작고 균일해서 캐릭터 자체보다 UI 박스가 더 먼저 보인다.

## 2. 현재 UI가 아마추어처럼 보이는 이유

- 문자열 깨짐 때문에 완성된 제품이 아니라 개발 중 임시 화면처럼 보인다.
- 카드, 버튼, HUD, 배경의 그라데이션과 그림자가 모두 강하게 들어가 시선 중심이 분산된다.
- 화면별 핵심 요소가 명확하지 않다. 홈은 플레이 버튼과 대표 캐릭터, 게임 화면은 점령률과 캔버스, 도감은 캐릭터가 가장 먼저 보여야 한다.
- 같은 역할의 버튼이 서로 다른 높이, 반경, 그림자를 사용한다. 예: `play-button`, `primary-button`, `small-primary-button`, `lobby-sub-button`이 각각 독립 스타일로 보여 통일감이 떨어진다.
- 일부 보조 메뉴가 비활성 상태로 배치되어 MVP에서 사용할 수 없는 기능처럼 보인다.
- 카드 내부의 뱃지, 진행바, 능력 설명, 상태 pill이 모두 비슷한 시각 무게를 가져 핵심 액션을 찾기 어렵다.
- 배경 장식, 캐릭터 bob 애니메이션, 버튼 shine, skill pulse가 동시에 존재해 작은 화면에서 산만하다.

## 3. 현재 UI가 모바일 게임이 아니라 웹앱처럼 보이는 이유

- 화면이 `max-width 430~450px` 중앙 정렬 컨테이너에 카드들을 쌓는 구조라 모바일 웹앱의 폼/대시보드처럼 읽힌다.
- 홈 화면에 정보 카드가 그리드로 나열되어 로비라기보다 상태 요약 대시보드처럼 보인다.
- 도감 화면이 카드 리스트 중심이라 수집 앨범, 보유/잠금, 대표 캐릭터 전시의 감성이 약하다.
- 게임 화면 HUD가 일반 통계 카드처럼 배치되어 캐주얼 게임 HUD 특유의 압축된 계기판 느낌이 부족하다.
- 비활성 버튼과 메뉴가 “곧 열릴 웹 기능”처럼 보여 게임 MVP의 짧은 플레이 루프를 흐린다.

## 4. 전체 아트 디렉션

방향은 “밝은 장난감 섬 로비 + 말랑한 수집 캐릭터 + 즉시 읽히는 플레이 HUD”로 잡는다. 배경은 흰색 기반 웹 페이지가 아니라 파스텔 하늘, 잔디 타일, 둥근 섬, 스티커 같은 캐릭터가 있는 모바일 게임 로비로 구성한다.

캐릭터는 이모지를 임시 자산으로 쓰더라도 단순 텍스트 이모지가 아니라 원형/캡슐형 캐릭터 받침대, 하이라이트, 그림자, 테마 타일과 함께 배치한다. UI는 장난감 버튼처럼 위쪽 하이라이트와 아래쪽 눌림 그림자를 가진다. 단, 모든 요소에 강한 효과를 주지 말고 플레이 CTA, 선택 카드, HUD 핵심 수치에만 강한 볼륨을 준다.

## 5. 디자인 키워드

- 캐주얼 모바일 게임
- 말랑한 수집감
- 밝은 섬 로비
- 탭하고 싶은 버튼
- 짧은 한 판 루프
- 점령률 즉시 인지
- 캐릭터 중심
- 파스텔이지만 선명한 CTA
- 웹 카드 최소화
- 한국어 우선 가독성

## 7. 타이포그래피 규칙

- 기본 폰트는 현재처럼 `Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`를 유지한다.
- 모든 한국어 문구는 UTF-8 정상 문자열로 관리한다.
- `letter-spacing`은 `0`을 유지한다.
- 화면 제목: 30~40px, font-weight 900~1000, line-height 1.05.
- 섹션 제목: 20~24px, font-weight 900, line-height 1.15.
- 카드 제목/캐릭터 이름: 17~20px, font-weight 900.
- HUD 숫자: 18~24px, font-weight 1000, line-height 1.
- HUD 라벨: 10~12px, font-weight 900, line-height 1.
- 버튼 텍스트: 주요 버튼 18~20px, 보조 버튼 14~16px, font-weight 900.
- 설명 문구: 13~15px, font-weight 700, line-height 1.4~1.5.
- 360px 이하 화면에서 제목은 최대 34px, HUD 라벨은 최소 10px을 유지한다.

## 8. 여백 규칙

- 앱 외곽 padding: 모바일 기본 `12px`, 390px 이상 `16px`, 640px 이상 `24px`.
- 화면 내부 세로 gap: 홈 `10~14px`, 게임 `8~10px`, 도감 `12~16px`.
- 카드 내부 padding: 작은 카드 `12px`, 일반 카드 `16px`, 대표 캐릭터 카드 `18px`.
- 버튼 내부 좌우 padding: 주요 CTA `18~22px`, 보조 버튼 `12~16px`.
- HUD pill 내부 padding: 세로 `6~8px`, 가로 `8~10px`.
- 캔버스 프레임 padding: `6~8px`.
- 하단 sticky CTA는 안전 영역을 고려해 `bottom: max(12px, env(safe-area-inset-bottom))`.

## 9. border-radius 규칙

- 앱 화면 큰 패널/히어로 섬: `26~30px`.
- 일반 카드: `20~24px`.
- 작은 카드/요약 pill: `16~18px`.
- 버튼: 주요 CTA `24~26px`, 보조 버튼 `18~20px`, 작은 버튼 `14~16px`.
- HUD pill: `16~18px`.
- 캔버스 외부 프레임: `28~30px`.
- 캔버스 내부 프레임: `20~24px`.
- 원형 아이콘/코인/생명: `999px`.
- 반경 값은 화면별로 새로 만들지 말고 위 토큰 안에서만 선택한다.

## 10. shadow 규칙

그림자는 “눌림 그림자”와 “공간 그림자”를 분리한다.

주요 버튼:

- 위 하이라이트: `inset 0 4px 0 rgba(255,255,255,0.55)`
- 아래 눌림: `0 8px 0 #C9782E`
- 공간 그림자: `0 14px 24px rgba(196,116,40,0.24)`
- active: `transform: translateY(5px)`, 아래 눌림 `0 3px 0 #C9782E`

보조 버튼:

- 아래 눌림: `0 6px 0 #6EC6B6`
- 공간 그림자: `0 10px 18px rgba(76,143,132,0.14)`

카드:

- 기본: `0 10px 22px rgba(74,137,162,0.12)`
- 선택 카드: `0 0 0 4px rgba(255,207,95,0.36), 0 14px 28px rgba(74,137,162,0.16)`
- 대표 캐릭터 카드: `inset 0 -8px 0 rgba(80,53,34,0.07), 0 18px 32px rgba(74,137,162,0.18)`

HUD:

- `inset 0 -4px 0 rgba(80,53,34,0.08), 0 7px 14px rgba(74,137,162,0.12)`

금지:

- 한 요소에 4개 이상의 강한 그림자를 중첩하지 않는다.
- 배경 장식에 강한 drop shadow를 남발하지 않는다.

## 11. 버튼 스타일 규칙

버튼 타입은 4개로 제한한다.

Primary CTA:

- 용도: 플레이하기, 게임 시작, 해금하기, 한 판 더.
- 높이: 홈 메인 `68~74px`, 일반 CTA `56~60px`.
- 배경: `linear-gradient(180deg, #FFE978 0%, #FFC84D 58%, #F2A63A 100%)`.
- 텍스트: `#4A2F1C`, 18~20px, 900~1000.
- 아이콘: 왼쪽 32~36px 원형 배지 안에 배치.
- 눌림 상태는 `translateY(5px)`로 반드시 제공한다.

Secondary CTA:

- 용도: 캐릭터 도감, 홈으로, 다시 선택.
- 높이: `50~56px`.
- 배경: `linear-gradient(180deg, #E9FFF9 0%, #A9F0DD 100%)`.
- 텍스트: `#1F6F63`, 14~16px, 900.

Icon Button:

- 용도: 뒤로가기, 홈, 일시정지.
- 크기: `42~48px`.
- 반경: `16~18px`.
- 텍스트 대신 `←`, `⌂`, `Ⅱ`처럼 즉시 이해되는 기호를 사용한다. 깨진 이모지 사용 금지.

Small State Button:

- 용도: 카드 내부 선택하기, 선택됨, 코인 부족.
- 높이: `42~46px`.
- 선택됨/비활성은 회색이 아니라 채도 낮은 크림색으로 처리하고 텍스트를 `#7A6048`로 둔다.
- 코인 부족 상태는 버튼을 비활성화하고 아래 보조 문구로 “코인이 부족해요”를 표시한다.

## 12. 카드 스타일 규칙

일반 카드:

- 배경: `rgba(255,255,255,0.82)` 또는 캐릭터 테마 그라데이션.
- border: `2~3px solid rgba(255,255,255,0.86)`.
- radius: `22px`.
- padding: `14~16px`.
- 카드 안에 또 다른 큰 카드를 넣지 않는다. 내부 정보는 pill 또는 얇은 stat row로 처리한다.

캐릭터 카드:

- 카드 상단에는 등급 배지와 상태 배지만 둔다.
- 중앙 45~50% 영역은 캐릭터 아바타가 차지한다.
- 캐릭터 이모지는 54~72px 크기의 원형 받침 안에 두고, 받침 아래에 타원형 그림자를 둔다.
- 이름은 아바타 바로 아래 18~20px, 굵게 표시한다.
- 능력 설명은 한 줄 또는 최대 두 줄로 제한한다.
- 잠금 카드는 전체 opacity를 낮추지 말고 아바타 우상단에 자물쇠 배지, 하단에 진행바를 둔다.
- 선택 카드는 외곽 노란 glow와 “선택중” 배지를 동시에 표시한다.

요약 카드:

- 홈 화면의 보유 코인, 최고 기록 같은 요약은 2개 이하로 제한한다.
- 3개 이상의 작은 대시보드 카드는 웹앱처럼 보이므로 피한다.

## 13. HUD 스타일 규칙

HUD는 게임 화면에서 캔버스보다 시각적으로 튀면 안 되지만, 점령률/목표/생명/코인은 즉시 읽혀야 한다.

구성:

- 상단 1행: 홈 버튼 42px + 캐릭터 정보 pill + 코인 pill.
- 상단 2행: 점령률 진행바 full width + 생명 표시.
- 점령률은 숫자만 카드에 넣지 말고 가로 progress bar를 함께 표시한다.
- 예: `점령 42% / 목표 70%` 텍스트와 8~10px 높이의 채워지는 바.
- 생명은 숫자보다 하트/동그라미 3개 표시가 먼저 보이게 한다.
- 코인은 `코인 +12`처럼 현재 판 예상 보상임을 명확히 한다.
- 스킬 버튼은 MVP에서 실제 기능이 없다면 제거하거나 “준비중” 비활성 버튼을 게임 화면 핵심 조작 아래에 작게 둔다. HUD 핵심 영역을 차지하지 않게 한다.

크기:

- HUD 전체 높이는 112px 이하를 목표로 한다.
- 360x700 모바일에서 캔버스가 화면 높이의 최소 48% 이상을 차지해야 한다.
- HUD pill 최소 터치 영역은 42px 이상.

상태 표현:

- 점령률 목표 80% 이상 도달 시 progress fill을 `#FFD75E`에서 `#68D36F`로 전환한다.
- 생명 1개 남음은 `#FF5F7D` 강조.
- 경로 충돌 피드백은 화면 중앙 상단에 1초 이하의 toast로 표시한다.

## 14. 홈 화면 리디자인 지시

목표는 “첫 화면이 바로 게임 로비로 보이는 것”이다.

레이아웃:

- 전체는 `app-shell--home` 안에 390~440px 모바일 로비 컨테이너를 유지하되, 카드 나열보다 세로 장면 구성을 우선한다.
- 상단: 코인 pill 왼쪽, 작은 설정/홈성 아이콘은 MVP에서 제거하거나 1개만 둔다.
- 중앙: 로고 + 대표 캐릭터 3종이 서 있는 섬 장면.
- 하단: 큰 플레이 버튼, 도감 버튼, 최고 기록 요약 순서.
- 비활성 미션/출석/상점/퀘스트류 버튼은 제거한다. MVP 범위 밖 기능처럼 보이기 때문이다.

홈 히어로:

- `PocketLand` 로고는 42~52px, 흰색 글자 + 청록 그림자 `0 4px 0 #3F9F8D`.
- 한국어 서브타이틀은 “귀여운 친구들과 땅을 넓혀보세요!”로 정상 표시한다.
- 캐릭터 3종은 중앙 땅냥이 112px, 좌우 캐릭터 80~88px로 크기 차이를 둔다.
- 캐릭터 이름 라벨은 캐릭터 아래 11~12px, 너무 긴 장식 없이 표시한다.
- 바닥은 잔디 타일 80~90px 높이로 두고, 점령 타일 3개를 색상 swatch처럼 배치한다.

홈 정보:

- 코인: 상단 pill에 `🪙 1,200` 형태.
- 최고 기록: 플레이 버튼 아래 작은 pill `최고 점령 72%`.
- 총 플레이 수는 MVP 핵심이면 `도전 12회` 정도로 작게 표시하고, 아니면 숨긴다.

홈 버튼:

- `플레이하기`는 화면 하단 20% 영역에서 가장 크고 명확해야 한다.
- `캐릭터 도감`은 Secondary CTA로 플레이 버튼 아래 2열이 아니라 full width 또는 48% 너비 1개 버튼으로 둔다.
- 하단 탭바는 MVP에서 홈/도감 두 개만 실제 이동이 가능할 때만 유지한다. 비활성 탭 2개 이상은 제거한다.

## 15. 게임 화면 리디자인 지시

목표는 “출시 가능한 플레이 화면처럼 보이고, 탭 조작을 방해하지 않는 HUD”이다.

레이아웃:

- 화면 순서: 상단 HUD, 캔버스, 하단 조작 힌트/보조 버튼.
- 캔버스는 정사각형을 유지하되 360x700 기준 최소 330px 이상 확보한다.
- 상단 헤더의 캐릭터 정보는 작게 줄이고, 난이도는 라벨 pill로 표시한다.
- 뒤로가기 버튼은 `←`가 아니라 홈 이동이면 `⌂` 또는 “홈” 아이콘으로 명확히 한다.

HUD:

- 점령률 progress를 가장 왼쪽/가장 넓은 영역에 둔다.
- 문구 예: `점령 42%` 큰 글자, 아래 `목표 70%`.
- 코인 pill 문구는 `예상 +18`로 표시한다.
- 생명은 `♥ ♥ ♥` 또는 원형 생명 3개로 표시하고 남은 수만 컬러 처리한다.
- 일시정지 버튼은 42px 아이콘 버튼으로 우측 끝에 고정한다.

캔버스 프레임:

- 외부 프레임은 장난감 보드처럼 `3px` 흰 border, 내부 `5px` 흰 border, 하단 눌림 그림자를 둔다.
- 캔버스 안 타일 색상은 캐릭터 테마와 연결한다.
- 땅냥이 owned tile: 연두 바탕 + 작은 발자국 패턴.
- 말랑젤리 owned tile: 민트/핑크 젤리 광택 점.
- 펭귄콩 owned tile: 아이스 블루 + 사선 얼음결.
- PATH는 모든 캐릭터 공통으로 노랑/흰 outline을 사용해 위험 경로를 즉시 인지하게 한다.

조작 힌트:

- 하단 문구는 `화면을 탭하면 방향 전환`으로 정상 표시한다.
- 힌트는 1줄 pill로 충분하다. 장문 설명 금지.
- 실제 기능 없는 스킬 버튼은 제거하거나 52px 비활성 원형 버튼으로 축소하고 `준비중` 배지를 붙인다. 다만 MVP 핵심 조작보다 강하게 보이면 안 된다.

결과 모달:

- 클리어: 제목 `클리어!`, 보상 코인 강조, `한 판 더` Primary CTA, `홈으로` Secondary CTA.
- 실패: 제목 `아쉽지만 다시 도전!`, 실패해도 받은 코인 표시, `다시 도전` Primary CTA.
- 모달 배경은 `rgba(59,47,35,0.42)` 딤 처리.
- 모달 패널은 320~390px, radius 28px, 상단에 캐릭터 이모지/메달 아이콘 64px 배치.

## 16. 캐릭터 도감 리디자인 지시

목표는 “리스트가 아니라 수집 앨범”으로 보이게 하는 것이다.

레이아웃:

- 상단: 뒤로가기 46px, 제목 `캐릭터 도감`, 코인 pill.
- 제목 아래: 수집 진행 pill `수집 1/3` + 진행바.
- 대표 영역: 선택 중 캐릭터 또는 다음 해금 캐릭터를 큰 카드로 노출한다.
- 하단: 2열 컬렉션 그리드. 360px 이하에서도 카드 폭이 156px 이상 나오도록 gap은 10~12px.

대표 캐릭터 카드:

- 높이 170~210px.
- 왼쪽: 등급, 이름, 역할, 능력.
- 오른쪽: 96~112px 캐릭터 아바타.
- 배경은 캐릭터 테마 그라데이션.
- 하단에 해금 진행바 또는 `선택중` 상태를 둔다.

컬렉션 카드:

- 카드 높이 230~260px.
- 상단: 등급 배지 왼쪽, 보유/잠금 상태 오른쪽.
- 중앙: 캐릭터 아바타 76~88px.
- 이름: 18px.
- 역할: 11~12px pill.
- 능력: 12~13px, 최대 2줄.
- 하단: 진행바 8px + 액션 버튼 42px.

잠금 상태:

- 잠금 캐릭터는 회색 처리만 하지 않는다.
- 캐릭터 실루엣은 60% 채도, 우상단 자물쇠 배지.
- 진행 문구는 `180/300 코인`처럼 실제 비용 기준으로 표시한다.
- 코인이 충분하면 버튼은 Primary CTA `해금하기`.
- 부족하면 비활성 버튼 `코인 부족` + 보조 문구 `120코인 더 필요`.

선택 상태:

- 선택된 캐릭터는 노란 외곽 glow, `선택중` 배지, 버튼 비활성 처리.
- 선택 버튼 텍스트는 `선택하기`.

캐릭터 카피:

- 땅냥이: 이름 `땅냥이`, 역할 `기본 친구`, 능력 `코인 보상 +5%`, 설명 `발자국 타일로 땅을 넓혀요.`
- 말랑젤리: 이름 `말랑젤리`, 역할 `초보 추천`, 능력 `이동 속도 -10%`, 설명 `천천히 움직여 실수를 줄여줘요.`
- 펭귄콩: 이름 `펭귄콩`, 역할 `가벼운 전략가`, 능력 `적 속도 -10%`, 설명 `차가운 얼음길로 방해꾼을 늦춰요.`

## 17. 컴포넌트 단위 구현 체크리스트

전역 CSS:

- [ ] UTF-8 한국어 표시가 정상인지 확인한다.
- [ ] 색상 토큰을 `:root` CSS 변수로 정리한다.
- [ ] 버튼 4종, 카드 3종, HUD pill 토큰을 재사용한다.
- [ ] 중복된 `.primary-button`, `.small-primary-button`, `.lobby-sub-button` 효과를 공통 규칙으로 통합한다.
- [ ] `@media (max-height: 700px)`에서 캔버스 최소 크기와 HUD 축소 규칙을 유지한다.

홈:

- [ ] 비활성 빠른 메뉴/하단 메뉴를 제거하거나 MVP 이동 버튼만 남긴다.
- [ ] 깨진 문구를 `포켓랜드`, `귀여운 친구들과 땅을 넓혀보세요!`, `플레이하기`, `캐릭터 도감`으로 교체한다.
- [ ] 플레이 버튼을 가장 큰 CTA로 유지하고 하단 근처에 둔다.
- [ ] 최고 기록 요약은 작은 pill 1개로 줄인다.
- [ ] 대표 캐릭터 3종이 첫 화면에서 즉시 보이게 한다.

게임:

- [ ] HUD를 점령 progress 중심으로 재배치한다.
- [ ] 코인 표시를 `예상 +n`으로 바꾼다.
- [ ] 생명은 시각 아이콘 3개로 표시한다.
- [ ] 조작 힌트는 `화면을 탭하면 방향 전환` 1줄로 줄인다.
- [ ] 실제 기능 없는 스킬 버튼은 제거하거나 비활성 보조 요소로 축소한다.
- [ ] 결과 모달 문구를 정상 한국어로 교체한다.

도감:

- [ ] `캐릭터 도감`, `친구 선택`, `보유`, `잠금`, `선택중`, `해금하기`, `코인 부족` 문구를 정상화한다.
- [ ] 대표 캐릭터 카드와 2열 그리드 구조를 명확히 분리한다.
- [ ] 카드 중앙 아바타 영역을 키우고 능력 설명은 최대 2줄로 제한한다.
- [ ] 잠금 진행바는 코인 비용 기준으로 표시한다.
- [ ] 선택 상태, 보유 상태, 해금 가능 상태, 부족 상태를 각각 시각적으로 구분한다.

접근성과 터치:

- [ ] 모든 주요 버튼 터치 영역은 최소 44px 이상.
- [ ] 텍스트 대비는 밝은 배경 기준 최소 4.5:1에 가깝게 유지한다.
- [ ] 아이콘만 있는 버튼은 `aria-label`을 정상 한국어로 제공한다.
- [ ] 움직임 애니메이션은 2~3종 이하로 제한한다.

## 18. 구현 우선순위

1순위: 문자열 정상화와 MVP 범위 정리

- 깨진 한국어/이모지 문구를 모두 정상화한다.
- 홈의 비활성 미션/출석/상점/퀘스트성 버튼을 제거하거나 숨긴다.
- 주요 버튼, HUD, 도감 액션 문구를 사용자가 즉시 이해할 수 있게 한다.

2순위: 디자인 토큰 통일

- 색상, radius, shadow, 버튼 높이, 카드 padding을 공통 규칙으로 맞춘다.
- 화면별로 새 그림자와 반경을 임의 생성하지 않는다.
- `global.css`가 유지되더라도 섹션 주석과 토큰 기반 순서로 정리한다.

3순위: 홈 로비 완성도 개선

- 대표 캐릭터 3종과 섬 장면을 첫 화면 중심으로 재배치한다.
- 플레이 CTA를 가장 강하게 만들고, 도감은 보조 CTA로 둔다.
- 요약 정보는 코인과 최고 기록 중심으로 줄인다.

4순위: 게임 HUD와 캔버스 프레임 개선

- 점령률 progress와 생명 표시를 즉시 읽히게 바꾼다.
- 캔버스 크기를 확보하고 HUD 압박을 줄인다.
- 캐릭터별 점령 타일 테마를 캔버스 렌더링에 반영한다.

5순위: 캐릭터 도감 수집감 강화

- 대표 카드 + 2열 그리드 구조로 정리한다.
- 보유/잠금/선택/해금 가능 상태를 명확히 구분한다.
- 캐릭터 아바타와 테마 배경을 카드의 중심 자산으로 키운다.
